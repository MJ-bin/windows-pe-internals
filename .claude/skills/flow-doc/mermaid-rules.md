# flow.md 구조와 머메이드 규칙

## flow.md 구조 (01_sprint 최종본 기준, 장 번호 유지)

```
# test.exe 실행 흐름 — 프로세스 생성부터 `main`까지
## 기준            빌드, pdb, 근거 로그 범위, sample 의존 관계, 표시 규칙 표
## 1. 흐름도       읽는 법 → 그림 1 (부모 cmd 스레드) → 그림 2 (test.exe 메인 스레드) [→ 그림 3.. 새 스레드]
## 2. 단계별 설명  2.1 ~ 2.10, 절마다 코드블록 트리 + 함수별 #### 와 태그 붙은 글머리
## 3. 같은 시간대의 다른 스레드
## 4. 공백 목록    표 + 4.1 추측으로 둔 호출 관계(그림의 ?) 표
## 5. 근거 run     run 표 (+ 이번 스프린트 sast/dast 번호)
```

- 새 절이 필요하면 번호를 끼워 넣지 말고 뒤에 붙이거나(2.11) 하위 절(2.5.1)로.
- "읽는 법"은 그림 규칙이 바뀔 때만 고친다.

## 그림 규칙 (검사기 `mmd_lint.py`가 R1~R6을 본다)

| # | 규칙 | 이유 (01_sprint에서 겪은 일) |
|---|---|---|
| R1 | 첫 줄 `flowchart LR` | caller → callee를 오른쪽으로 그리기로 함 |
| R2 | **모든** `subgraph` 바로 다음 줄 `direction LR` | mermaid 11은 상자 안을 기본값(TB)으로 그려 세로로 쌓임 |
| R3 | 호출 화살표 `-->` 라벨은 `+0x..`(관찰) 또는 `?`(추측), 앞에 `(n) ` 가능 | 근거 없는 호출이 관찰처럼 보이지 않게 |
| R4 | 한 그림 = 한 스레드, 그림 안 노드는 **모두 이어져야** 함 | 끊어진 덩어리는 위아래 순서를 mermaid가 마음대로 바꿈 (③→②→① 거꾸로) |
| R5 | 한 caller가 여러 callee를 부르면 **모두** `(1) (2) (3)` | 위아래 자리는 순서가 아님. 버전마다 다르게 배치됨 |
| R6 | `flowchart TD` / `graph TD` / `TB` 금지 | TD + 상자 안 상자면 mermaid 12가 LR을 무시 |

검사기가 못 보는 규칙 (직접 지킨다):

| # | 규칙 | 이유 |
|---|---|---|
| R7 | **함수 하나 = 노드 하나.** 여러 함수를 한 노드에 `→`로 뭉치지 않는다. 재귀·두 번 불림도 따로 노드 | 사용자 지적: "왜 뭉개버렸어?" |
| R8 | 상자 순서: 스레드 상자 > 모듈 상자. **같은 모듈은 한 상자** (ntdll을 단계별로 쪼개 따로 두지 않는다) | 사용자 지적: "같은 ntdll이잖아" |
| R9 | 단계 구분이 필요하면 **모듈 상자 안의 상자**로 (예: ntdll 안 `(1) kernel32 준비`) | |
| R10 | caller는 **한 번만** 그리고 거기서 가지를 친다. 같은 함수를 단계마다 다시 그리지 않는다 | 사용자 지적: LdrpInitializeProcess 중복 |
| R11 | 점선 `-.->` 돌아옴은 **다음 번호 호출이 관찰된 곳에만** | 돌아온 걸 본 게 아니라 다음 호출을 본 것 |
| R12 | 굵은 `==>` = 호출이 아닌 실행 넘어감 (커널→유저 등) | |
| R13 | 같은 무렵 다른 스레드 일 = 노란 메모 노드 `:::side`, 이을 땐 `-.-` | R4를 지키면서 시간 위치 표시 |
| R14 | 색 = 모듈 (`classDef`): kern 분홍 / ntdll 파랑(default) / k32 초록 / dll2 보라 / dll1 노랑 / exe 청록. 추측 노드는 같은 색 + 점선 테두리(`…g` 클래스) | |
| R15 | 다른 모듈 상자는 오른쪽에 모인다 → "오른쪽 상자 위치는 호출 깊이와 무관"이라고 읽는 법에 적혀 있음 | |
| R16 | `[dll1 추정]` 처럼 대괄호 = 그때 맡은 모듈. 확인되면 "추정"을 뗀다 | |

## 노드·간선 예 (01_sprint 그림 2에서)

```
    subgraph T2DLL["ntdll"]
        direction LR
        c4["ntdll!LdrpInitializeProcess"]
        subgraph PH1["(1) kernel32 준비"]
            direction LR
            k1["ntdll!LdrpInitializeKernel32Functions"]
        end
    end
    c4 -->|"(1) +0x19a2"| k1
    k1 -.-> c4
    k10 -->|"?"| d1
    b2 ==>|"커널 → 유저 전환 (공백)"| c1
    g1 -.- w1
```

- 라벨에 `(`, 공백이 있으면 큰따옴표로 감싼다.
- 노드 ID는 영어·숫자만. 표시 글자는 `["..."]` 안에, 줄바꿈 `<br/>`.
