# flow-doc Skill

한 바퀴의 결과를 **run 문서 한 장**으로 남기고, 그 내용을 **flow.md**에 합친다.
그림(mermaid)은 **글을 다 고친 뒤 맨 마지막**에 그린다. 그림은 글의 요약이지, 글보다 앞서면 안 된다.

## 표시 태그

| 태그 | 뜻 | 근거 |
|---|---|---|
| `[관찰]` | 디버거로 **실행을 직접 본 것** | `ms/logs/*.txt` 의 줄 |
| `[정적]` | 디컴파일·디스어셈블 **코드에 그렇게 쓰여 있는 것**. 실행 때 그 길로 갔는지는 모름 | `ms/disassemble/<m>/<f>.asm` 의 `+0x` 줄, `_workspace/sast/*_result.md` |
| `[소스]` | `sample/` 소스·빌드 스크립트에 쓰여 있는 것 | 파일과 줄 |
| `[추측]` | 위 셋에서 짐작한 것, 일반적으로 알려진 설명 | 짐작의 이유를 같이 적는다 |
| `[공백]` | 아직 아무것도 못 본 구간 | — |

- run 문서의 "표시" 칸은 지금처럼 `[26100.9457 확인]`(= 관찰) / `[정적]` / `[확인 필요]` 를 쓴다.
- `[정적]`과 `[관찰]`이 같은 걸 말하면 둘 다 적는다 (예: `[관찰]` run7 콜스택 + `[정적]` asm `+0x284` call). 둘이 다르면 **고치지 말고** 다르다고 적고 4장 공백 목록에 넣는다.
- 추측을 관찰로 올리는 건 근거 파일이 있을 때만.

## Workflow

1. **입력 모으기**: 오케스트레이터가 준 경로들을 읽는다 — sast 요청서·결과서, dast 요청서·runbook, `ms/logs/NN_키워드.txt`·`_result.md`, 필요하면 `ms/decomp`, `ms/disassemble` 의 해당 함수 파일.
2. **스프린트 폴더 확인**: `runs/NN_sprint/flow.md` 가 없으면 바로 전 스프린트의 `flow.md` 를 **복사**해서 시작한다. 복사했다고 보고에 적는다. 이전 스프린트 파일은 건드리지 않는다.
3. **run 문서 쓰기**: `runs/NN_sprint/runN-키워드.md` — [run-template.md](run-template.md) 양식. 로그·결과서에 있는 것만 쓴다.
   - 결과서·`_calls.tsv` 에 `alias:` 로 나온 함수를 문서에 언급해야 하면, Ghidra 가 고른 이름을 그대로 쓰지 말고 하는 일(예: "0을 돌려주는 빈 함수")로 적은 뒤 "같은 주소 이름 N개, 후보: …" 를 한 줄 붙인다. 이름 전부는 `pdb_aliases.py --lookup <모듈> <0xRVA>`.
   - 이전 run이 틀렸던 게 드러나면 "정정" 절을 쓰고, 이전 run 문서 맨 위에도 정정 안내를 한 줄 넣는다 (run7 방식).
4. **flow.md 글 고치기** (그림은 아직):
   - "기준"의 근거 로그 범위, 2장 해당 절, 3장(다른 스레드), 4장 공백 목록·4.1 추측 표, 5장 근거 run 표.
   - 채워진 공백은 지우지 말고 `(해결됨) … → runN` 으로 남긴다.
   - 태그를 바꾼 곳(추측 → 관찰 등)은 run 번호를 붙인다.
4-1. **짐 지도 고치기** (오케스트레이터가 "짐 지도 바퀴"라고 했을 때): `runs/NN_sprint/baggage.md` — [baggage-template.md](baggage-template.md) 양식. 없으면 양식으로 새로 만든다.
   - 사진(`ms/logs`·판정)·결과서·run 문서에 있는 칸만 쓴다. 3장 표를 먼저 고치고, 2장 요약 숫자를 3장 줄 수에 맞춘 뒤, 1장 그림을 고친다.
   - 이번 바퀴에서 새 호출 관계가 나왔으면 flow.md 도 4·5번대로 고친다 (흐름도는 대표 지점 규칙 그대로).
5. **그림 다시 그리기**: [mermaid-rules.md](mermaid-rules.md) 규칙대로. 4번에서 바뀐 호출 관계만 반영한다 (`?` → `+0x..`, 새 노드, 점선 테두리 해제 등).
6. **검사**:
   ```bash
   bash .claude/skills/flow-doc/scripts/check_mermaid.sh runs/NN_sprint/flow.md
   ```
   - `== 결과: 통과 ==` 가 나올 때까지 고친다 (최대 3번). 그래도 안 되면 위반 내용을 그대로 보고한다.
   - `SKIP` (node 없음)이면 lint만 통과한 것이라고 보고한다.
7. **보고**: run 문서 경로, flow.md에서 바뀐 절 목록, 태그가 바뀐 줄 수, 새로 생긴 공백, 검사 결과. 짐 지도 바퀴면 baggage.md 에서 바뀐 절과 2장 요약 숫자도.

## 하지 않는 것

- 로그나 결과서에 없는 함수 이름·오프셋을 쓰지 않는다. 기억나는 Windows 지식은 `[추측]`으로만.
- 디컴파일 코드를 문서에 길게 붙이지 않는다 (MS 코드. 몇 줄 요약 + 파일 경로만, 그 파일은 커밋되지 않는다).
- 덤프 원본(`ms/dump/`)을 문서에 붙이지 않는다. 칸 이름과 값 요약만 쓴다.
- 그림을 보기 좋게 하려고 노드를 합치거나 빼지 않는다 ([mermaid-rules.md](mermaid-rules.md) R7).
