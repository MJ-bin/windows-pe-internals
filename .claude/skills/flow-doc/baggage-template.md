# 짐 지도 양식 (`runs/NN_sprint/baggage.md`)

초기화 동안 nt·ntdll이 **어느 공간에 무엇을 어떻게** 세팅하는지, 그리고 **지도의 어느 경로**로 하는지를 한 장에 모은다.
짐 지도 바퀴(pe-flow-cycle 단계 4)마다 flow-writer가 고친다. 처음이면 이 양식으로 새로 만든다.

## 맨 위

```markdown
# 짐 지도 — 초기화 동안 nt·ntdll 이 세팅하는 것

## 기준
- 빌드 26100.9457, 대상 test.exe (sample/)
- 범위: 프로세스 생성 (`NtCreateUserProcess`) → 은퇴 (`NtContinue` 로 `RtlUserThreadStart` 에 가는 순간)
- 근거: run 범위, 사진 (dast NN)
```

## 쓰는 말 (문서 맨 위에 그대로 둔다)

- **공간**: `유저` (에뮬레이터 가상 주소 공간, 게스트가 직접 읽음) / `커널` (에뮬레이터 바깥, nt 엔진·syscall로만 닿음)
- **단계**: `①` 커널 단계 (`NtCreateUserProcess` ~ 유저로 넘어가기) / `②` ntdll 단계 (`LdrInitializeThunk` ~ `NtContinue`)
- **놓는 법**:
  - `직접`: 함수가 칸에 바로 쓴다 (커널은 새 프로세스에 붙은 상태에서 유저 칸에 바로 쓴다)
  - `주소 넘김`: 칸 주소를 넘기고, 받은 함수가 쓴다
  - `붙이기`: 파일·섹션 내용을 주소 공간에 붙인다
  - `syscall`: ntdll이 syscall을 부르면 커널이 채운다
  - `입력`: 부모·부팅·파일·레지스트리에서 온 값
- **쓴 주인**: `nt` / `ntdll` / `다른 DLL` (KERNELBASE·KERNEL32 등 — 범위 밖, 표시만) / `사용자 코드` (TLS·DllMain)
- **태그**: flow-doc 표시 태그 그대로 (`[관찰]` / `[정적]` / `[소스]` / `[추측]` / `[공백]`)

## 1. 공간 그림

- 코드 블록 안의 글자 나무로 그린다 (머메이드 안 씀).
- 모양: 공간 → 구조체·메모리 구역 → 단계 표시 (`①`/`②`).
- 3장에 없는 짐은 그리지 않는다. 모르는 곳은 `[공백]` 을 붙여 둔다.

## 2. 구조체별 요약

| 구조체·구역 | 공간 | 칸 수 | nt 가 씀 | ntdll 이 씀 | 다른 DLL | 0 그대로 | 아직 모름 |
|---|---|---|---|---|---|---|---|

- 칸 수는 PDB 직접 칸 기준. 숫자는 3장 표의 줄 수와 맞아야 한다.

## 3. 짐 표 (구조체·구역마다 절 하나)

| 칸 | 단계 | 무엇을 (값·모양) | 놓는 법 | 쓴 주인 | 경로 (지도 기준) | 근거 |
|---|---|---|---|---|---|---|

- 경로는 함수 이름 사슬로 쓴다: `→` 부름, `⇒` 꼬리 JMP. 오프셋은 마지막 함수 뒤에만 (`LdrpInitializeProcess +0x1c1`).
- 빌드끼리 비교하는 열쇠는 **이름**(함수 이름, PDB 칸 이름)이다. 오프셋은 덧붙이는 정보.
- 0 그대로인 칸도 줄을 남긴다 ("아무도 안 씀" + 근거).
- 같은 칸을 두 번 쓰면 (예: 커널이 쓰고 ntdll이 덮음) 줄을 나눠 둘 다 적는다.

## 4. 두 공간 짝

| 유저 쪽 | 커널 쪽 | 무엇이 맞아야 하나 | 근거 |
|---|---|---|---|

- 예: 핸들 값 ↔ 핸들 표, 이미지 ↔ 섹션 객체·구역 장부, 맡긴 문맥 ↔ 트랩 프레임.

## 5. 단계 순서

- `①`, `②` 각각, 짐이 놓이는 순서를 지도 호출 순서대로 적는다.

## 6. 공용 부품

| 부품 | 하는 일 | 끝까지 본 run | 쓰는 줄기 |
|---|---|---|---|

- 여러 줄기에 나오는 함수(복사·할당·문자열·락 등)는 여기서 한 번만 끝까지 보고, 3장에서는 이름으로 가리킨다.

## 7. 빈 곳

- `[공백]` 칸과 "아직 모름" 칸을 모은다. 오케스트레이터가 `_workspace/plan.md` 대기열로 옮긴다 (출처: baggage.md).

## 8. 근거 run

| run | 무엇을 채웠나 |
|---|---|

## 하지 않는 것

- 덤프 원본(`ms/dump/`)이나 디컴파일 코드를 붙이지 않는다. 칸 이름과 값 요약만 쓴다.
- 사진·결과서·run 문서에 없는 칸 값이나 쓴 자리를 지어내지 않는다. 모르면 `[공백]`.
- "구현할지 말지"로 칸을 빼지 않는다 (구현 범위는 목록이 다 된 뒤 사용자가 정한다).
