## 먼저 읽는 한 줄 답

**질문 1 (파라미터 표)**: **3 과 7 은 서로 다르고, 7 은 8 과 같다.** 요청 NDR 2.0 바이트 꼴은:
- **8 = 7** (요청): 객체 UUID 16 B 가 **그대로 인라인** (참조 포인터 — ID 없음) · 탑 (conf · `tower_length` · octets, 4 정렬) **인라인** · **SID 포인터 ID 4 B (`FC_UP`)** (+ 있으면 SID 본문) · 이어받기 핸들 20 B · `max_towers` 4 B. 7 이 8 과 다른 것은 **비동기 핸들이 없다는 것뿐** (Oi2 `0x43` ↔ `0xc3`, 스택 자리 −8) — 스텁 바이트는 8 과 같다.
- **3**: 객체 · 탑이 **전체 포인터 `FC_FP`** 라 각각 **포인터 ID 4 B 가 앞에 붙고** (0 이 아니면 그 뒤에 본문), **SID 칸이 아예 없다** (파라미터 7 개). 핸들 20 B · `max_towers` 4 B 는 같다.
- 응답은 셋 다 같다 (핸들 20 · 탑 수 · 배열 머리 · 원소 ID · 탑 · 상태). 선 위 응답 128 B (탑 1개 · octets 73) / 40 B (탑 0개).
- **요청 스텁 길이 (탑 octets 66)**: 3 = **124 B** (객체 · 탑 둘 다 있음; 객체 NULL 이면 108) · 7 SID NULL = **120 B** · 7 SID 있음 = **132 + 4n B** (n = SID 하위 권한 수; n=1 → **136**). SID 칸만 따로 보면 NULL = 4 B, 있음 = **16 + 4n B** (ID 4 + conf 4 + 머리 8 + 4n).
- **원문 "확인 거리" 표와 칸마다 맞다.** 다른 칸 없음. 02 가 안 적은 것만 더했다: 3 에는 SID 가 없다 · 클라이언트가 3 / 7 / 8 중 하나를 고르는 조건 (아래 7절).

**질문 2 (run145 `:264` 정정)**: 그 줄 "3 · 7 은 요청 NDR 꼴만 다름 (`FC_FP`)" 은 **틀렸다**. 고쳐 읽기: "**7 은 8 과 요청 NDR 꼴이 같고 (객체 · 탑 참조 = 포인터 ID 없음 · SID `FC_UP`, 비동기 핸들만 없음), `FC_FP` 포인터 ID 가 붙는 건 3 뿐이다 (3 은 SID 칸도 없다)."** 그대로 넣을 글은 8절. **NDR64 쪽도 같은 관계다** (3 = `0x23` 포인터 둘, 7 = 8 = 참조 + SID `0x21`, 9절).

**클라이언트 쪽 (덤)**: `LookupNextChunk` 는 **비동기면 8, 동기 + SID 없음이면 3, 동기 + SID 있음이면 7** 을 부르는 코드를 가졌다 (7절). 그래서 r19 의 7 (197 샘플) 은 요청에 **SID 가 실려 온다** (이 클라이언트 코드에선 "7 + SID NULL" 이 안 나온다).

- **SID 길이 식**: SID 가 있으면 칸 전체가 `4 (ID) + 4 (conf = n) + 8 (머리) + 4n = 16 + 4n` B, NULL 이면 4 B. 길이 전체 = `(24 + 4 정렬된 octets 길이 + 20 + 4)` + SID 칸 = 탑 66 일 때 `116 + SID 칸`.
- 탑 octets 길이 L 이 달라질 때: 3 = `56 + 4 정렬(L)` (객체 · 탑 둘 다 있음) · 7 = `48 + 4 정렬(L) + SID 칸`. L = 73 이면 3 = 132 · 7 SID NULL = 128 · 7 SID n=1 = 144.
- 포인터 ID 값 (3 의 객체 · 탑 ID 가 얼마인가): 선 위 값은 정적으로 안 정했다 `[공백]`. 서버는 0 / 0 아님만 가르면 된다. 같은 ID 가 두 번 나오면 둘째는 본문이 안 따라온다 (NDR 전체 포인터 규칙 `[규칙]`) — 객체와 탑 ID 는 서로 달라야 한다.
- `max_towers`: 클라이언트 코드가 **4** 를 상수로 넣는다 (8 `LookupNextChunk +0xe6 MOV dword [RSP+0x48],4` · 3 `+0x143 MOV dword [RSP+0x38],4` · 7 `+0x181 MOV dword [RSP+0x40],4`).
- 응답 스텁 (셋 다 같다): 3 · 7 · 8 의 출력 칸 차례 = 핸들 20 → `num_towers` 4 → 배열 (max_count · offset · actual_count · 원소 ID × n · 탑마다 `[len][len][octets]` 4 정렬) → 상태 4. **탑 1개 · octets 73 → 128 B, 탑 0개 → 40 B** (run137 3-1 과 같다). 3 의 배열 크기 칸은 스택 `0x20` (`max_towers`), 7 은 `0x28`, 8 은 `0x30`.
